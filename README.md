# Сервис форм для карьерной платформы

Менеджер сам собирает форму отклика в админке, публикует её по уникальной ссылке; студент заполняет; менеджер смотрит ответы. Плюс — **аналитика отказов**: видно, на каком вопросе студенты бросают форму.

## Запуск

```bash
npm install
npm start
```

Откройте **http://localhost:3000/admin** (без авторизации). Порт настраивается: `PORT=4000 npm start`.

* Node.js ≥ 20, **внешних зависимостей нет** (только встроенные модули) — `npm install` ничего не скачивает.
* Данные хранятся в `data/db.json` (создаётся автоматически; запись атомарная — через временный файл).
* Тест ключевого сценария: `npm test`.

## Как пользоваться

1. `/admin` → **«Новая форма»**: название, описание, вопросы (9 типов: короткий/длинный текст, email, телефон, число, дата, выпадающий список, один из списка, несколько из списка), обязательность, подсказки, порядок (↑/↓).
2. Отметить **«Опубликована»** → **Сохранить** → появится ссылка вида `/f/k3x9a1bz`. Скопировать и отправить студентам.
3. Студент открывает ссылку, заполняет, отправляет.
4. **Ответы** в админке: таблица, удаление, выгрузка в CSV (открывается в Excel), статистика.

## Что сделано и почему

| Решение | Причина |
|---|---|
| Фокус на ключевом сценарии MVP из 4 шагов | Задание просит «выбрать главное», а не реализовать всё |
| **Аналитика воронки**: открыли → начали → отправили + «на каком вопросе ушли» | Вторая проблема из ТЗ — «причина низкой конверсии неизвестна». Без этого менеджер так и не узнает, почему бросают |
| **Автосохранение черновика** в браузере студента | Прямо снижает число брошенных форм: случайно закрыл вкладку — ответы на месте |
| Индикатор прогресса | Студент видит, сколько осталось |
| Валидация и на клиенте, и на сервере | Клиентская — для удобства, серверная — для надёжности |
| Slug ссылки — 8 случайных символов (~2·10¹²) | Нельзя угадать/перебрать чужую форму |
| Черновик/опубликована | Менеджер может готовить форму, не показывая её студентам |
| Удаление вопроса не ломает старые ответы | Ответы хранят снимок названия вопроса; в таблице/CSV колонка помечается «(удалено)» |
| Отрисовка через DOM API, без `innerHTML` | Защита от XSS: названия вопросов и ответы студентов — пользовательский ввод |
| CSV: защита от формул (`=`, `+`, `-`, `@`) | Студент не сможет внедрить формулу в таблицу менеджера |
| JSON-файл вместо SQLite | Не нужны нативные сборки и доп. зависимости — запуск гарантированно двумя командами |

### Как считается аналитика
Страница студента шлёт лёгкие события: «открыл форму» и «кликнул в поле N» (один раз на поле). Сервер хранит по сессии список затронутых полей и последнее. «Ушли на вопросе» = у скольких брошенных сессий этот вопрос был последним. Данные анонимны (случайный id сессии на вкладку, без cookie и персональных данных).

## Структура

```
server.js            HTTP-сервер, API, валидация, хранилище (≈350 строк)
public/admin/        админка (конструктор, список, ответы+статистика)
public/form.html/js  публичная форма для студента
test/smoke.js        сквозной тест сценария
data/db.json         данные (создаётся при запуске, в .gitignore)
```

## API (кратко)

* Админка: `GET/POST /api/forms`, `GET/PUT/DELETE /api/forms/:id`, `GET /api/forms/:id/responses`, `GET /api/forms/:id/responses/export.csv`, `DELETE /api/forms/:id/responses/:rid`
* Публичное: `GET /api/public/:slug`, `POST /api/public/:slug/submit`, `POST /api/public/:slug/track`

## Осознанные ограничения (что сделал бы дальше)

* **Нет авторизации** — по условию ТЗ. В проде `/admin` и `/api/forms*` обязательно закрыть.
* **Нет защиты от спама** публичной формы (капча, rate limit) — первое, что стоит добавить.
* JSON-файл подходит для сотен форм и десятков тысяч ответов; дальше — SQLite/Postgres (слой хранилища изолирован в `server.js`).
* Не реализовано: условная логика (показать вопрос по ответу), загрузка файлов (резюме), уведомления менеджеру о новом отклике, дублирование формы, срок приёма заявок и лимит откликов.
* Аналитика считает «дошёл до вопроса» по клику в поле; для мобильных/автозаполнения можно уточнить событием `change`.
